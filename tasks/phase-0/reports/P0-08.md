## Done

"Send to all" as a queue the staff watch drain: a compose form with a recipient picker, one
`message_out` per recipient stored before the first transmission, a queue over P0-05's
outbox with a minimum gap between transmissions and a countdown, retry from the queue, and
re-queueing of pending messages after a reload. Nothing new is persisted: batches live in
memory, every status is derived from the journal.

- `store/outgoing.ts` (P0-05 file) — `batchPreview(lastSeqNos, body)`: the byte counter for
  the longest `#n ` prefix among the chosen recipients (`previewText` of the highest last
  `#n`); `composeBatch(store, { incidentId, operator, counterpartyIds, body })`: one
  `composeMessage` per recipient in order, mesh only, each reserving that recipient's own
  next `seqNo` in the store's write transaction (no new store API); refuses a repeated or
  empty recipient list before writing; a failure part-way throws `BatchComposeError` with
  `stored` (the messages already written, which are real journal entries), the failing
  `counterpartyId` and the `cause`.
- `store/index.ts` — app wrappers `composeBatch` (operator from settings) and
  `lastSeqNos(ids)` → `Map<id, last #n>`.
- `radio/sendQueue.svelte.ts` — `createSendQueue(deps)` with `store`, `outbox`, `now`,
  `gapMs` (read before every gap), `radioState`, `onConnected`, `log`. `enqueue(messages)`
  makes a `Batch` (`batch-N`, created time, `restored`, items with message id, incident,
  counterparty, `seqNo`, text) and appends the ids to `waiting`; one loop takes the head,
  waits out the gap since the previous transmission *ended* (`nextTransmissionAt`,
  `countdownMs()`), waits for a radio if there is none (`phase` `paused`, woken by
  `onConnected`), hands the message to `outbox.send` (`phase` `sending`, `sending()`), awaits
  `delivered` / `given_up`, and goes on; an `OutboxError` (the message's status moved while
  it waited, or a second holder) is kept in `errors()` and the queue carries on.
  `retry(ids)` puts messages of earlier batches back into `waiting` (no new batch, no new
  `message_out`). `requeuePending(incidentId)` finds the incident's mesh `message_out`
  entries whose derived status is `pending` and that nobody holds, oldest first, and queues
  them as a restored batch. `earliestStartMs(id)` and `drainEstimateMs()` count the gaps
  alone (see *Decisions*). `revision()` for screens, `stop()` for tests and teardown. The
  loop only awaits when it has to wait, so the phase right after `enqueue` is never `idle`.
- `radio/index.ts` — the app's `sendQueue` (gap from settings, radio state and
  `onConnected` from the radio store); on start and on every incident change
  `requeuePending(currentIncidentId())` runs, which is how the queue survives a reload.
- `lib/settings.svelte.ts` — `sendGapSeconds`, default 10, 1–600, loaded through the same

- `components/BatchComposeForm.svelte` — recipients as a checkbox list (label, street, the

## Decisions taken

- **The task was inferred** (note at the top); third run in a row without a task section.
- **The queue is a separate screen (`#/queue`), with the compose form on it**, not a mode of
  the journal's compose form. The brainstorm calls the queue "one of the most important
  screens in the tool"; it needs the width for 25 rows and the totals. The journal screen
  still shows every message of the batch in its timeline and open items, so nothing is
  hidden from the journal.
- **The gap is measured from the end of the previous transmission** (the outbox resolving
  with `delivered` / `given_up`), not from its start. "At least the gap" then holds
  whatever the ack window and the resends did; a message that took 60 s to give up is
  followed by a 10 s gap like any other. Measured by the queue's own clock, re-checked when
  the timer fires, so an early timer cannot shorten it.
- **The queue pauses while the radio is disconnected or connecting** (the fix-next in
  `FOLLOWUPS.md`), woken by the radio store's `onConnected`. The outbox's own "no radio →
  given up at once" is unchanged for single sends from the journal screen. A connect that
  fails leaves the queue paused. `blind` counts as connected, as it does for the compose
  forms.
- **The compose form still refuses to send to all without a radio**, as P0-05's form does,
  even though the queue would pause. One rule for both forms; the pause is for a radio that
  goes away mid-batch (and for a reload with no radio yet).
- **"Estimated time to drain" is a lower bound from the gaps alone**: the countdown plus one
  gap per further waiting message; transmissions and receipt waits come on top. Shown as "at
  least X". Anything closer to an estimate would be a guess at round-trip times, which
  nothing in the contract defines. `null` (not shown) while paused.
- **The status chip is the derived status; the outbox's and the queue's progress texts
  replace it only while they hold the message.** The attempt column shows `k/max` only while
  the outbox holds the message; after that the resend notes in the journal are the record.
  Counting resend notes to show "3 attempts" afterwards would read the journal by convention
  rather than by contract, so it is not done.
- **Retry does not make a new batch or a new `message_out`**: the message keeps its `#n` and
  its row; `retry` is the same `outbox.send` the journal's Retry does. Given-up messages of a
  batch from before a reload are not in the queue's memory; the journal screen's Retry covers
  them.
- **Re-queueing on start covers the current incident only**, and runs again when the incident
  is changed, as the inbox's drain does. Pending mesh messages of other incidents stay where
  they are; a pending message in a closed incident from last week should not go out because
  the app was opened.
- **A failure in the middle of composing keeps the stored messages and queues them.**
  Entries are immutable, so the alternative was a batch of real messages nobody sends. The
  only failure the UI can reach is a text that fits the longest prefix at preview time but
  not at write time, which needs the counter to move in between (another writer); the form
  re-reads the counters after every send.
- **The pending ones of a reload mid-flight are transmitted anew** with a fresh timestamp, so
  the recipient may get the same text twice if the radio had already sent it before the
  reload. The journal has one `message_out` either way (the acceptance's "none is sent twice
  … checked by `seqNo`"). The companion's own retry with the same timestamp cannot survive a
  reload (the outbox keeps the timestamp in memory); noted under *Follow-ups*.
- **No dependency added.** Prettier was run on the four new files only, as in P0-07.
- Candidates for `docs/decisions.md`: the gap is between the end of one transmission and the
  start of the next; the send-to-all queue pauses without a radio; the drain time shown is a
  lower bound from the gaps; re-queue on start is per current incident.

## Follow-ups

- [ ] The prompt of this run lacked its `--- TASK ---` section, as P0-06's and P0-07's did.
      Three in a row: `run-all.ps1`'s prompt assembly loses the task file on this machine.
- [ ] A reload mid-flight loses the outbox's sender timestamp, so the re-queued message goes
      out as a new transmission (new timestamp) and a recipient whose radio already got the
      first one sees the same `#n` text twice. Keeping the last timestamp per message in the
      store would need a contract change (nothing in the schema holds it); a note entry would
      be reading the journal by convention. Decide whether the duplicate is acceptable (it
      carries the same `#n`, so the field person can tell).
- [ ] Given-up messages of a batch sent before a reload are not in the queue's memory, so the
      queue screen's "Retry all" does not see them; the journal screen's Retry does. A
      "restore the given-up ones too" button on the queue screen would be a small addition.
- [ ] The queue screen's batch table is not windowed; 25 rows per batch is fine, a drill with
      ten batches of 25 is a long page.
- [ ] `queue.item.earliest` and the drain line say "at least"; once real drain times exist
      (manual check), consider adding the measured average per message to the estimate — a
      measured number, not a guess.
- [ ] The compose form's street select uses the register's `street` field as typed; two
      spellings of one street are two streets. The register screen could offer the existing
      streets as a datalist (P0-03 territory).
- [ ] `recordManualStatus` still does not know about the outbox or the queue (P0-07
      follow-up); the queue now records the outbox's refusal in its `errors()` and goes on,
      which is the visible half of that.
- [ ] `home.placeholder` still says "The journal comes in a later step"; the home screen could
      point at the journal and the queue, or go away (P0-07 follow-up).
- [ ] No component-level tests (as before): the recipient picker, the countdown tick and the
      row texts are exercised by hand only.
- [ ] Prettier: the touched P0-02 to P0-07 files are still unformatted (`npm run
      format:check`); one `npm run format` commit after the phase.
