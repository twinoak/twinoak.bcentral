## Decisions taken

- **Router: hash-based, hand-rolled** (`router.svelte.ts`, ~25 lines). No dependency, works
  from `file://` and from a GitHub Pages sub-path without server config, and four screens do
  not justify a library. Candidate for `docs/decisions.md`.
- **Icon: generated at build time, not committed.** `scripts/make-icon.mjs` writes two PNGs
  (navy square, light disc inside the maskable safe zone) with a 60-line PNG encoder on top
  of `node:zlib`, no image dependency. It runs as `predev`/`prebuild`; the PNGs are
  gitignored so no binaries enter the repo. The same disc is `public/icon.svg` for the
  favicon. Candidate for `docs/decisions.md` (no binaries in the repo).
- **`lint` runs ESLint only.** Prettier is configured (`format`, `format:check`) but not part
  of `npm run lint`, so Verify does not fail on formatting alone. `eslint-config-prettier` keeps
  the two from disagreeing. If the reviewer wants formatting enforced, add `format:check` to
  `lint`; it is one word.
- **The Promise rule covers `allSettled`/`race`/`any` too**, not only `Promise.all`. Same
  convention ("no promise plumbing"); one selector with a regex.
- **i18n keys are flat and dotted** (`settings.operatorName`), not nested objects. Makes the
  completeness test a key-set comparison and the grep for keys trivial.
- **Language names are shown in their own language** ("Dansk", "English") in both catalogs.
- **Settings use an explicit Save** with drafts, rather than saving on every keystroke;
  language changes apply and persist immediately (it is a select, not text).
- **Blind-after accepts whole minutes ≥ 1**; the number input yields `undefined` when empty
  and that is treated as invalid.
- **Dependencies beyond the stack decision** (all dev, all implied by "ESLint + Prettier" and
  "svelte-check"): `@eslint/js`, `typescript-eslint`, `eslint-plugin-svelte`,
  `eslint-config-prettier`, `globals`, `prettier-plugin-svelte`, `svelte-check`,
  `@types/node` (for `node:fs`/`node:url` in tests and the icon script). Runtime: `ulid`
  (in the stack decision). Versions are caret ranges; `ulid` is `^2.3.0 || ^3.0.0` because
  the session could not query the registry to confirm the current major.
- `vite-env.d.ts` references `svelte` and `vite/client` types instead of restricting
  `types` in tsconfig, so `@types/node` is visible to the tests.
- Added `"svelte/no-navigation-without-resolve": "off"` (a SvelteKit rule in
  `eslint-plugin-svelte` ≥ 3.10's recommended set) since this is plain Vite with hash links.
  If the installed plugin is older than 3.10 and ESLint complains the rule does not exist,
  delete that line.
