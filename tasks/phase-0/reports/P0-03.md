## Done

The register screen at `#/register`, the store rules behind it, the contact picker's
interface with a fake, and the "current incident" the edit notes attach to.

- `store/db.ts` — **database version 2**: a unique `by-publicKey` index on `register`. The
  upgrade is stepwise (`oldVersion < 1` creates the P0-02 layout, `< 2` adds the index), so a
  browser that already has a version-1 database from P0-02 keeps its data.
- `store/journalStore.ts`:
  - `DuplicatePublicKeyError` (carries `publicKey` and `existingId`).
  - `putRegisterEntry` now runs in one readwrite transaction: validate, look the key up in
    `by-publicKey`, throw `DuplicatePublicKeyError` if another id holds it, then `put`. The
    unique index is the second line of defence (and also guards `importEnvelope`).
  - `createRegisterEntries(inputs)` — the ad hoc batch: all entries validated first, then
    one transaction with the same key check per entry (earlier adds in the transaction are
    visible, so a key repeated within the batch is caught too). All or nothing.
  - `registerEntryByPublicKey(key)`, `isIncidentOpen(id)` (exists, and the latest
    `status_change` referring to it is not `closed`; none yet = open).
- `store/register.ts` — the register's rules:
  - `PUBLIC_KEY_PATTERN` read from `contract/journal.schema.json` (`$defs.publicKey.pattern`),
    `isValidPublicKey`, `normalizePublicKey` (trim + lowercase, nothing else).
  - `adhocLabels(first, count)` → `"radio #first"` … via `t("register.adhocLabel")`.
  - `registerChanges(before, after)` over the seven editable fields (stamps excluded; absent
    and empty read the same), `registerChangeText(before, after)` → the journal line, e.g.
    `register: radio #7 → Hans, Street (none) → Nørregade`, `null` when nothing changed.
  - `saveRegisterEntry(store, entry, { operator, incidentId })`: `put`, then — only if the
    entry existed before, something changed, an incident id is given and that incident is
    open — `appendEntry` of a `note` with that text. Returns `{ entry, note | null }`.
  - `sortedByLabel(entries, locale)`: `Intl.Collator(locale, { numeric: true, sensitivity:
    "base" })`, ties by id; "radio #2" sorts before "radio #10".

## Decisions taken

- **Proceeded although P0-02 is not merged** (see the status note). The alternative was an
  empty report. Flagged for the reviewer; not a precedent.
- **Uniqueness of the public key is both an explicit check and a unique index.** The check
  gives a named error with the holder's id (the form shows which entry has the key); the
  index (database version 2) makes it impossible to bypass through `importEnvelope` or a
  future write path. The check runs inside the write transaction, so two concurrent saves
  cannot both pass it. If a developer's version-1 database already holds two entries with one
  key (only possible through P0-02's `putRegisterEntry`, by hand), the upgrade fails with a
  `ConstraintError`; wipe the database in DevTools. No real data exists yet.
- **"Current incident" is a one-id holder in `lib/`, persisted in localStorage.** The task
  needs "the current incident, if one is open" and nothing defined "current" yet. The holder
  is the smallest thing that P0-07's incident bar can own later; "open" is answered by the
  store from `status_change` entries (`closed` / `reopened`), not stored on the holder.
  Candidate for `docs/decisions.md` only if P0-07 keeps it; otherwise it is an implementation
  detail.
- **The note is only written for edits of existing entries, not for additions.** The task
  says "every edit". Whether handing out a new radio during an incident should also leave a
  journal line is listed under *Follow-ups*; it is a one-line change in `saveRegisterEntry`.
- **Note text is built with `t()`**, i.e. in the UI language at the time of the edit, with the
  task's shape: `register: <old label> → <new label>, <Field> <old> → <new>, …`. More explicit
  than the task's example (`register: radio #7 → Hans, Nørregade`): the field name is named,
  and `(none)` marks an empty side, so the line says what changed and from what. Origins are
  written as their UI words; keys in full (a key change is rare and must be exact). The
  conventions say user-facing strings go through `t()`; the journal is read by the staff, so
  the note counts. The cost: the stored text depends on the language the operator had
  selected, and the test pins the English form.
- **Register write first, note second**, in two transactions. The register change is what
  the staff asked for; the store has already rejected an invalid entry or a taken key before
  the note is attempted, so the only way to get an un-noted edit is `appendEntry` failing on
  a valid note (operator name empty, which the app gates against). Accepted over a combined
  transaction, which would have moved the entry-write logic out of `appendEntry`.
- **Pasted keys are trimmed and lowercased, nothing more.** Hex is case-insensitive and the
  contract stores lowercase, so folding loses nothing; a `0x` prefix, spaces inside or a
  wrong length are rejected, not repaired.
- **The ad hoc batch does not pre-fill the key fields and does not guess the first number.**
  Default 1; if "radio #1" already exists the row says so and the staff picks another start.
  Labels are not unique in the schema, so this is a screen rule for this flow only; a normal
  edit can still give two entries the same label.
- **The picker does not fill the label from the contact's advertised name.** The brainstorm
  calls the binding deliberately manual; the key is the binding, the name is typed.
- **Sorting uses `Intl.Collator` with `numeric: true`.** "radio #10" after "radio #2" is what
  the staff expect from a stack of numbered radios. Locale is the UI language.
- **Batch size capped at 100** in the form (not in the store). Enough for one stack; keeps
  the screen usable.
- **Contact shape is minimal** (`publicKey`, `name`). The task did not ask to read meshguide
  for this task, and the session could not read outside the repo anyway. P0-04 may widen the
  interface (last advert, type) without touching the picker, which only uses these two.
- `removeStorage` added to `lib/storage.ts` so clearing the current incident removes the key
  rather than storing an empty string.
