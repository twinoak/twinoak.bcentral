## Decisions taken

- **One mirror file per device, not per incident** (the task's lean): one file to find in a
  crisis; the incident is on every line (`incidentId`).
- **The kinds are `incident`, `registerEntry`, `entry`** — the task's literal example
  (`{"kind":"entry", …}`) for entries and the contract's words for the other two.
  `CONVENTIONS.md` would say `journalEntry`; the task's example wins, and `entry` is the
  store's own word (`appendEntry`, the `entries` store). Flagged for `docs/decisions.md`.
- **Choosing a folder writes a full export file first, then the `.ndjson` carries what
  follows.** The task names the export file only "on every export"; without a starting point a
  folder chosen mid-incident would miss everything before it, and the goal is "if the laptop
  dies, the staff still have the journal". Appending the whole store to the `.ndjson` instead
  would duplicate lines when the same folder is chosen twice; the parser tolerates that, but
  the file should stay the plain log of writes.
- **A failed line is kept, not dropped.** The task asks that failures be shown and never
  block the write; the mirror also keeps the line at the head of the queue and writes it when
  the folder is back, so nothing is lost while the app is open. Only `forget()` drops the
  queue. The settings page shows "N lines waiting".
- **A write is retried on the next write, not on a timer**: a failing folder is reported once
  per write and recovers by itself when it returns; no polling.
- **`NotAllowedError` is `needsPermission`, everything else is `error`.** The permission case
  has a one-click remedy (the top-bar button calls `requestPermission` inside the click); the
  rest ("folder gone", "disk full") is shown with the browser's message and links to settings.
- **The storage warning goes away once a folder is set**: its own text names the remedy;
  showing it after the remedy would be noise. Under About the storage line still says what the
  browser answered.
- **A missing `navigator.storage.persist` (or a throw) counts as refused**: nothing was
  promised. Chromium always has it; the line would show in a browser the README rules out
  anyway.
- **"Since last print" includes a row when anything it folds in is at or after the stored
  time** — a message sent before the last print whose receipt or roger came after it, a note
  corrected after it, a batch where one recipient moved. The paper would otherwise never show
  the changed strip. "At or after" rather than "after": an entry stamped in the same second as
  the print is printed twice rather than never.
- **The print time is the load time, and it is stored after `print()` returns.** What is on
  paper is what was loaded; entries arriving between load and the click are in the next
  print. `window.print()` blocks until the dialog closes and the browser does not say whether
  the operator printed or cancelled, so a cancelled dialog also moves the time — the view
  says "Printed {time}" and the previous time is one reload away. Flagged under
  *Open questions*.
- **One "Print journal" button; the print view defaults to "since last print" when there was
  one.** The task calls the since option "the routine button"; the routine is Print journal →
  Print, with the since box already ticked. A second button on the incident bar would save
  nothing.
- **Oldest first on paper, the screen's newest first on screen**, both from the same
  `buildTimeline`; inside a batch the recipients stay in transmission order on both.
- **History is not printed**: the strip is P1-01's folding; the transitions are on the screen
  under History. The clock-trust mark is printed (a `?` on paper says the time was not
  confirmed).
- **Page numbers**: CSS `@page` margin boxes (`counter(page) / counter(pages)`); where a
  Chromium version does not draw them, its own print header/footer (on by default) carries
  "page x of y", and the document title is the incident name during the print. Manual check.
- **The `meta` value type is widened, no database version bump.** `counter()` reads the
  numeric keys so the arithmetic stays typed; a counter key never holds anything else.
- **The strip / counters / history words moved to `lib/journalText.ts`** from
  `Timeline.svelte` rather than duplicated: the print view must say what the screen says.
  `Timeline.svelte` imports them; its behaviour is unchanged.
- **`importEnvelope` notifies too**: an import is a write; a mirrored import makes the
  walkthrough a round-trip test. When a restore path arrives (phase 2), restoring a mirror
  file into a store with the same folder set would append it all again — the parser keeps one
  line per entry id, so the file stays readable; worth a decision then (*Follow-ups*).
- **No dependency added. `contract/` untouched.** The `.ndjson` carries the contract's shapes
  unchanged; the file format is the app's, described in `mirrorFile.ts` and the README.
  Prettier: the new files, `main.ts`, `app.css`, `en.json`, `da.json` (formatted before) are
  formatted; `Timeline.svelte`, `TopBar.svelte`, `IncidentBar.svelte`, `SettingsPage.svelte`,
  `App.svelte`, `index.ts`, `router.svelte.ts`, `db.ts`, `journalStore.ts` and the test were
  unformatted before and are left so (P1-01 follow-up stands). The editor turned eight LF
  files into CRLF during the run; they were turned back before the commit.
- Candidates for `docs/decisions.md`: the mirror is one append-only NDJSON per device with
  the kind first and the contract's shapes; choosing a folder writes an export file as the
  starting point; "since last print" is by what changed in a row.

## Follow-ups

- [ ] A cancelled print dialog moves the last-print time (the browser does not say); if that
      bites in a drill, an "Undo: previous print was {time}" link on the print view is one
      meta write.
- [ ] Restore/merge from a mirror file is not built (phase 2's restore path): `parseMirror`
      + `mirrorEnvelope` + `importEnvelope` are the pieces; decide then whether an import
      with the same folder set should be mirrored (it would append every line again).
- [ ] `appendLine` copies the existing file on every write (`keepExistingData`), so a write
      costs the file's size; fine for a journal (hundreds of KB), worth a check on a
      multi-day incident with a slow USB stick. `FileSystemSyncAccessHandle` (workers only)
      or a per-day file would fix it.
- [ ] The mirror file holds the register entries' edits as repeated lines; the register's
      journal note is the audit trail, the file is a log. Said in `mirrorFile.ts`.
- [ ] `@page` margin boxes: confirm which Chromium versions draw them; the reviewer's print
      says. The `@page` rule is in `app.css` because Svelte's scoped styles cannot carry it.
- [ ] The print view has no component test (as every screen); the folding is tested in
      `printView.test.ts`, the page's "print time stored only after print()" is by reading.
- [ ] `persisted()` is read once on start; Chromium can grant persistence later (after the
      PWA is installed in the same session). A re-check on `visibilitychange` would clear the
      line without a reload.
- [ ] The staff README's folder paragraph is English; P1-09's Danish review covers the UI
      only.
- [ ] `tasks/CONVENTIONS.md` says `journalEntry`; the mirror says `entry` (the task's own
      example). One line in the conventions, or a rename of the kind before a hub reads
      these files.
- [ ] Prettier: the P0/P1 files listed under *Decisions* are still unformatted; one
      `npm run format` commit after the phase (P1-01 follow-up).
- [ ] `docs/decisions.md` candidates listed under *Decisions taken*.
