## Decisions taken

- **`untrack` rather than `$state.snapshot`.** `$state.snapshot(entry)` would still be a
  top-level read of `entry` and would still warn; `untrack(() => entry)` is the compiler's
  own documented way to say "the initial value, on purpose". One call instead of seven
  keeps the reason in one place. The form's behaviour is unchanged: it never followed a
  changed `entry` before either (and does not need to, see the `{#key}`).
- **Already-fixed lines are ticked `(fixed in P1-03: already done by …)`** naming the commit
  that did it, so the tick form the task asks for and the truth both hold.
- **Item 4's acceptance was taken as met by the existing test.** It toggles a fake
  transport's connection twice, which is what "a fake link toggling state" describes;
  rewriting it with a stub `radioState()` function would test less (the real store's
  state transitions would be out of the loop).
- **No `docs/decisions.md` candidate**: nothing here is a new rule.
