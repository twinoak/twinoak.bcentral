## Done

The association's resident list goes into the register in one step, the register comes back
out as a file Excel opens as it is, and a printable list goes in the box.

- **Reading the file.** `store/registerCsv.ts` (new, pure): `stripBom`, `detectSeparator` (a
  `;` in the header line makes `;` the separator, else `,`), `parseCsvRecords` (a small
  state machine: fields quoted with `"`, `""` for a quote inside, separators and line breaks
  inside quotes, CRLF or LF, a record whose every field is empty is a blank line and not a
  row; the one failure is a quote not closed by the end of the file), `matchHeader` (names
  trimmed and compared case-insensitively against `label, person, street, role, origin,
  publicKey, notes`; an empty name, an unknown name, a repeated name and a missing `label`
  are each an error naming the column), `previewRegisterImport(text, existing)` → every row
  with the fields as they will be stored and its own errors, plus the file's errors, and —
  only while there is no error at all — the `entries` (rows with a key) and `pending` (rows
  without) ready for the store. Row rules, each an error naming the line (the header is line
  1, a quoted line break does not shift the count): wrong field count, empty label, origin
  not `issued` / `adhoc` / `private` (case folded, empty = `issued`), key not 64 hex after
  `normalizePublicKey` (trim + lowercase, as the form does), the same key earlier in the file
  (both lines named), the key already in the register (the holding entry's label named).
  `csvErrorText(error)` renders each through `t()`. Optional fields are trimmed and stored
  absent when empty, as the form does.
- **Writing the file.** `registerCsv(entries, pending)`: BOM, the seven columns, `;`, CRLF,
  a field quoted only when it holds `;`, `"`, CR or LF, one line per entry in the order
  given, then the pending rows with an empty key. `csvField` is the quoting rule.
- **Pending rows.** A row without a key is not a `registerEntry` (the schema requires the
  key), so it is kept in the store's `meta` under `pendingRegister:<id>` (`db.ts`:
  `META_PENDING_REGISTER_PREFIX`, `metaPendingRegisterKey`, `pendingRegisterKeyRange`;
  `MetaValue` widened; no database version bump — `meta` is untyped). `types.ts`:
  `PendingRegisterRow` = a `RegisterEntry` without `publicKey` (same id and stamps),
  `NewPendingRegisterRow`. `journalStore.ts`: `importRegister(entries, pending)` — entries
  validated and stamped first, pending rows validated as the entry they will become (with a
  placeholder key), then one readwrite transaction over `register` + `meta`: every key
  checked against the store and the rows before it (`assertPublicKeyFree`), entries added,
  pending rows put in meta; all or nothing; `onWrite` for each entry and for no pending row
  (the mirror carries the contract's objects only). `pendingRegisterRows()` (a key range over
  the prefix), `getPendingRegisterRow(id)`, `bindPendingRegisterRow(id, fields)` — one
  transaction: the row is read, the entry is built from the given fields with the row's id,
  `createdAt` and `createdOnDevice`, validated, the key checked, added to `register`, the
  meta key deleted; `NoPendingRowError` when the id is not pending. `journalFolder()` now
  tells the handle from a pending row (both are objects under `meta`). `putRegisterEntry` and
  `createRegisterEntries` open their transaction with `objectStore("register")` so one
  `RegisterWriteStore` type serves every register write.
- **The write with its note.** `store/registerImport.ts` (new): `importRegister(store,
  preview, {operator, incidentId, fileName})` refuses a preview with errors or no rows

## Decisions taken

- **Pending rows live in `meta`, under their own id, and keep that id when bound.** The task
  says "kept in `meta`"; the id and stamps minted at import stay on the entry the row
  becomes, so a bound row is the row the list showed, and a later merge sees one object.
  The row is validated at import as the entry it will become (placeholder key), so binding
  can only fail on the key. Pending rows are not in the envelope, not mirrored and not in
  the journal folder: they are not contract objects. A laptop that dies between import and
  handout loses them, but not the CSV they came from. Flagged under *Open questions*.
- **The separator is decided by the header line alone**: a `;` anywhere in it means `;`,
  else `,`. A header holding both is split on `;` and the leftover (`person,notes`) is an
  unknown column, named — the file says what is wrong instead of the app guessing.
- **A record whose every field is empty is a blank line**, dropped like an empty line. Excel
  leaves `;;;;;;` for a deleted row; refusing the file for it would be strictness without
  information. A record with some fields empty and the wrong count is still an error.
- **Origin is matched case-insensitively after trimming**, like the headers and like the key
  (hex case folded); `udleveret` or a typo is an error. Empty is `issued` as the task says.
- **Line numbers, not row numbers.** An error names the line the record starts on, the
  header being line 1, which is what an editor shows; a quoted line break does not shift
  the count (the test pins it).
- **The note counts every row imported** ("imported 5 entries from beboere.csv, 3 not yet
  bound to a radio"): the task's text, with the pending count added so the journal says what
  the box will find. Written through `t()` in the UI language, as the edit note is (P0-03;
  the mixed-language follow-up from P1-01 stands). Only for an open incident, none when
  none is selected, as for an edit.
- **Binding takes the form's fields, not only the key.** The pending row seeds the form and
  the staff may correct a name while they have the radio in hand. No journal note for a
  bind: it creates a register entry, and additions do not note (P0-03's rule).
- **The CSV export is a download only**, not written into the journal folder: the folder
  holds the contract's files (the `.ndjson` and export envelopes); the register is in both
  already. One line in `exportRegisterCsv` if wanted (*Follow-ups*).
- **The print view is its own route** (`#/register/print`), like the journal's, with the
  pending rows under their own heading and an empty key column: the box list should say who
  has no radio yet. Nothing is recorded after a print.
- **No dependency added.** Prettier was run on the new files and on the touched files that
  were formatted before (`App.svelte`, `RegisterForm.svelte`, `RegisterPage.svelte`,
  `router.svelte.ts`, `db.ts`, `export.ts`, `register.ts`, `en.json`, `da.json`);
  `index.ts`, `journalStore.ts` and `types.ts` were unformatted before and are left so
  (P1-01 follow-up stands). No file came out of the editor as CRLF this time (checked).
- Candidates for `docs/decisions.md`: the register's file format (the seven columns, `;`,
  BOM, CRLF; `,` accepted on import); a row without a key is a pending row kept outside the
  contract until bound; the id survives the binding.

## Follow-ups

- [ ] Pending rows are outside the contract: not exported in the envelope, not mirrored to
      the journal folder, so a laptop that dies after the import and before the handout
      loses them (the CSV still exists). If that bites, the envelope could carry them in an
      app-owned side file, or the contract could make `publicKey` optional — a contract
      decision.
- [ ] `exportRegisterCsv` downloads only; writing the CSV into the journal folder too is one
      `mirror.writeFile`-style call if the staff want it on the stick.
- [ ] There is no way to drop a pending row that was imported by mistake; an entry is never
      deleted, but a pending row is not an entry. A "Remove" on the pending list is one meta
      delete, if the users want it.
- [ ] A pending row's label is not checked against the register or the other pending rows;
      two "Hans" rows import fine (the schema allows equal labels; only the ad hoc batch
      checks). Same as P0-03's follow-up.
- [ ] The import's preview table is not paged; 300 rows is one long screen. Fine for one
      association.
- [ ] No component tests (as before): the file input, the preview, the bind form and the
      print view are by hand only; the rules are in `registerCsv.test.ts`.
- [ ] `docs/decisions.md` candidates listed under *Decisions taken*.
- [ ] Prettier: `index.ts`, `journalStore.ts`, `types.ts` still unformatted; one
      `npm run format` commit after the phase (P1-01 follow-up).
