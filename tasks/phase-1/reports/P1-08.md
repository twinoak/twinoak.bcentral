## Decisions taken

- **"Close with a reason" records `roger` by hand.** The contract has one way an item leaves
  the staff's queue — roger is final, "Roger closes the item in the staff's queue" — and
  P0-07 lets the operator record a roger on a mesh message by hand with a reason; the
  timeline's Set status → Mark roger is the same write. A new "closed" status for messages
  would change the data model (out of scope). The reason is in the history, so the journal
  says it was the operator, not the field.
- **"Send by courier" is one click: the courier copy, then the original closed with the
  reason "sent by courier as #n".** The alternative — leave the original given up and let the
  operator Close it afterwards — leaves a decided item under "needs a decision" and costs a
  second click. The copy is written first, so a refused close leaves a visible copy and the
  original still listed. The copy carries no `refersTo` (the store only allows a `message_in`
  there, P1-02) and no link to the original; the reason text names the copy's #n. Flagged
  under *Open questions*: a roger that no field radio sent.
- **The handover note is the task's literal text, not through `t()`**: `handover: ‹old› →
  ‹new›` in every UI language, so a reader (the hub, a human) finds every handover by the same
  words; the register note (`register: …`) is translated, so this is an exception, said in
  the code. Candidate for `docs/decisions.md`, and for the P1-01 follow-up about journal texts
  in the UI language.
- **The note is stamped with the operator taking over**, written before the settings change
  (a refused note leaves the name as it was); the incoming operator signs the handover in.
  Same name (trimmed) = no handover, nothing written, the button disabled.
- **`Meld status` is a constant, never through `t()`**, like `ØVELSE ` (P1-05): it is on-air
  text read on Danish phones, the same whatever the UI language.
- **"Unanswered" = no `message_out` refers to it and no roger was recorded from it.** The
  second rule is read off the roger `status_change`'s text, which the contract says is the
  incoming entry's id; a manual roger's text is a reason and matches nothing. An incoming
  message linked to an order by hand (the P1-02 open question) would need a rule here once
  that link exists.
- **"Quiet" = not heard from within the blind time (`settings.blindAfterMinutes`), over the
  whole journal**, as the "last heard from" panel counts (drills included, P1-05); the order is
  that panel's (never first, then the oldest contact).
- **Given up is its own list, not among the open orders** (the task's four lists); the
  journal's open-items panel still flags them inline, unchanged.
- **The lists are oldest first** (the task: "the overdue one on top"), the one screen where
  the P1-01 open question (newest versus oldest first) is answered by the task itself.
- **The page prints itself** rather than a `#/handover/print` route: the lists on paper are
  exactly the lists on the screen, and the two names are known only here (the typed name is
  not stored anywhere). A print-only header carries the time and the names; after a Take over
  on this visit the printed time and names are the note's. P1-04's app.css rules do the rest.
- **Retry on the handover page is `outbox.send`** (the journal screen's path), not the queue's
  `retry`: the row is one message, whichever batch it came from; the queue screen keeps its
  own Retry all.
- **Reply stays on the page**: P1-02's `ComposeForm` is mounted under the lists and
  `replyTo(entry)` is called on it, so the new operator answers without leaving the handover;
  the sent reply is transmitted as on the journal screen.
- **Send status request needs a connected (or blind) radio**, as the compose form does;
  otherwise the button is disabled with the no-radio sentence as its tooltip, rather than
  storing a message the outbox would at once give up.
- **The clock box is the settings' control verbatim** (session state, `lib/clock.svelte.ts`);
  nothing new is stored.
- **No dependency added. `contract/` untouched.** Prettier was run on the new files; `en.json`,
  `da.json`, `App.svelte` and `router.svelte.ts` were formatted before and still are;
  `TopBar.svelte`, `store/index.ts` and `README.md` were unformatted before and are left so
  (P1-01 follow-up stands). No file came out as CRLF.
- Candidates for `docs/decisions.md`: closing a given-up message is a manual roger with a
  reason; "send by courier" is a courier copy plus that close; the handover is one untranslated
  note `handover: ‹old› → ‹new›`; quiet = silent for longer than the blind time over the whole
  journal.

## Follow-ups

- [ ] "Send by courier" and "Close" both record a `roger` that no field radio sent (with the
      reason in the text). If the users want to tell a staff decision from a real roger in the
      journal, that is a new status in the contract (a `closed` on messages), or a `note`
      with `refersTo` plus an app rule to hide decided items — a contract decision.
- [ ] The handover note is untranslated (`handover: …`) while the register note is
      translated; one rule for the journal texts the app writes (P1-01 follow-up) would settle
      both.
- [ ] The printed handover has no "since" and no page break between the lists; a long "Open
      orders" pushes "Quiet radios" to page 2. Fine for a dozen orders; a 25-recipient batch
      with no rogers is 25 lines.
- [ ] A status request to a radio whose "last heard" is `never` goes out like any other; the
      page does not say whether the radio has ever been seen on the mesh (the companion's
      contact list knows). A "not in the radio's contacts" mark on the quiet list would be
      one lookup in `radio.contacts()`.
- [ ] The compose form on the handover page is the full P1-02 form (any recipient, any
      transport); it is there for Reply. If it invites composing from the handover page, a
      narrower "reply only" form is a prop on `ComposeForm`.
- [ ] No component tests (as before): the ticking ages, the Take over button's enabling, the
      close form on the row, the print header and `replyTo` from this page are by hand only.
- [ ] `handover.column.age` ("Age" / "Alder") and the other Danish strings are first drafts
      for P1-09's review ("Vagtskifte" for the screen, "Tag over" for the button).
- [ ] Prettier: `TopBar.svelte`, `store/index.ts` and `README.md` remain unformatted (P1-01
      follow-up).
- [ ] `docs/decisions.md` candidates listed under *Decisions taken*.
