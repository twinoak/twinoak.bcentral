## Decisions taken

- **The prefix follows the incident in the store, not a flag the caller passes.**
  `composeMessage` reads the incident by `incidentId` and prefixes when it is a drill, so no
  path (compose form, send-to-all, a reply) can store a drill's text without it. One extra
  read per message; nothing new is stored. An incident the store does not have (imported
  data, the tests' fixed ids) is not a drill.
- **`drill: true` is stored for a drill; a real incident has no `drill` key**, so the real
  incidents of this task look exactly like the ones before it (the schema's "absent means a
  real incident"). A caller that puts an explicit `drill: false` keeps it as given (valid,
  same kind). The mirror lines and exports carry the flag as stored.
- **Immutability is the store's rule**, not the UI's: `putIncident` reads the stored incident
  inside its own transaction and refuses to flip the flag (`DrillChangeError`), both ways and
  also by dropping the key. There is no UI to edit an incident; the guard is there for
  whatever comes (import/merge, a later edit screen). `importEnvelope` writes incidents
  directly and bypasses it — it is phase 2's restore path and takes the file as it is
  (*Follow-ups*).
- **The export holds the current incident's kind: drills only while a drill is current, real
  incidents only while a real one is, everything while none is selected.** The task's "the
  journal export file name carries -drill" and "kept apart in exports" could also be read as
  a per-incident export; the kind-scoped file keeps the README's promise that the export is
  the whole real journal ("export it after every incident") while a drill never lands in
  it, and the drill file holds every drill. The no-incident case is the plain backup it
  always was (the journal folder's starting export, written by `chooseFolder`, is the same
  unscoped file). Flagged for `docs/decisions.md`; also *Open questions*.
- **The `-drill` suffix is derived from the file's content** (`isDrillEnvelope`: every
  incident a drill, at least one), so `envelopeFilename` names the download, the folder copy
  and any future file the same way without a flag threaded through; a mixed file is never
  called a drill file.
- **The incident name's prefix is translated ("DRILL: name" / "ØVELSE: name"); the band's
  word, the window title and the batch row's text are the on-air word in both languages.**
  The task says the on-air prefix is `ØVELSE` everywhere; the name prefix is UI, and in the
  English UI "DRILL:" says what it is. The band reads "ØVELSE / DRILL" as the task spells it,
  in both catalogs (a catalog value may be the same in both languages; nothing checks that
  they differ).
- **The switcher shows the two headings only once there is a drill**; with real incidents
  alone the list is as it was. A single "Incidents" heading over everything would be noise.
- **The batch row's "ØVELSE #n body" is read off the stored text** (`isDrillText`, exact
  prefix for the message's own `seqNo`), not off the incident, like `bodyOf`: the row says
  what went on the air, which is what the text is. A message whose text happens to start with
  "ØVELSE" but not with its own `#n` is shown as it is.
- **The band is not printed**; the print view has its own framed DRILL line in the header,
  and `document.title` during a print carries "DRILL: name". A band is screen chrome like the
  top bar (`no-print`), and CSS cannot repeat it per page.
- **"Last heard from" counts drill traffic** (the task's lean) with the heading's tooltip
  saying so; `lastHeardFrom` is unchanged.
- **Re-queue on start needs no new guard**: `requeuePending` has always read one incident's
  entries, so a drill's messages cannot be queued into a real incident's session. The
  acceptance line is pinned by a test rather than by code. A batch already in the queue when
  the operator switches incident keeps transmitting (as before P1-05); its texts are stored
  with or without the prefix and go out as stored.
- **`drillMode` is a store module** (`store/drillMode.svelte.ts`), wired in `store/index.ts`
  like the mirror, because it needs the store and `lib/` must not import `store/index.ts`
  (a cycle). The current incident id stays in `lib/currentIncident.svelte.ts`, unchanged.
- **No dependency added.** Prettier was run on the new files and on the touched files that
  were formatted before (`ComposeForm.svelte`, `BatchComposeForm.svelte`, `Timeline.svelte`,
  `LastHeardPanel.svelte`, `PrintPage.svelte`, `App.svelte` unchanged by it, `journalView.ts`
  and its test, `export.ts` and its test, `journalText.ts`, `sendQueue.svelte.ts` and its
  test, `en.json`, `da.json`, `main.ts`, `schema.test.ts`); `outgoing.ts`, `journalStore.ts`,
  `incidents.ts`, `index.ts`, `IncidentBar.svelte`, `JournalPage.svelte`, `QueuePage.svelte`
  and their tests were unformatted before and are left so (P1-01 follow-up stands). The
  editor turned three LF files into CRLF during the run (`QueuePage.svelte`, `incidents.ts`,
  `incidents.test.ts`); they were turned back before the commit.
- Candidates for `docs/decisions.md`: a drill is decided at creation and never changes; the
  on-air prefix is `ØVELSE ` before `#n ` on every transport and is part of the stored text;
  the export is scoped to the current incident's kind and a drill file is named `-drill`; the
  register and "last heard from" are shared.

## Follow-ups

- [ ] `contract/text-protocol.md` still heads its section "Drill mode — proposed, not
      decided" and says "If adopted"; the task allows the schema only. One line in a
      `tasks:`/contract commit: it is decided, and the prefix is on every transport.
- [ ] `importEnvelope` bypasses the drill guard (it puts incidents as they are). When the
      restore/merge path arrives (phase 2), decide whether a file that flips an existing
      incident's flag is refused or taken.
- [ ] The queue screen's batch headings ("Batch of 14:31, 25 recipients") do not say drill;
      the rows' texts do (`ØVELSE #n …`) and the band is on the screen. A "(drill)" in the
      heading is one key if the walkthrough asks for it.
- [ ] Incoming messages land in the current incident, drill or real (`docs/open-questions.md`
      §1 stands): a field radio that still answers a real order while the desk has switched
      to a drill files its answer under the drill. The band makes the switch visible; the
      rule is still the users' to decide.
- [ ] The export made while no incident is selected holds drills and real incidents mixed
      (the full backup). If that ever confuses, the Export button could be hidden until an
      incident is selected, like Print.
- [ ] The journal folder's `.ndjson` is still one file per device (P1-04's open question): a
      drill's lines are in it, told apart by `incidentId` and by the incident line's
      `"drill": true`. The export files in the folder are apart (`-drill`). A second
      `.ndjson` per kind is a small change in `mirror.svelte.ts` if wanted.
- [ ] No component tests (as before): the band, the checkbox, the optgroups, the pill and the
      print line are by hand only.
- [ ] `docs/decisions.md` candidates listed under *Decisions taken*.
- [ ] Prettier: the files listed under *Decisions* are still unformatted; one `npm run
