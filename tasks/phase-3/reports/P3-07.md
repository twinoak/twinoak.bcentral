## Done

An outgoing message by phone, courier or in person is a plain record: the text as typed, no
`#n`, no prefix, no byte limit, no status, nothing to mark. The radio's receipt chain is
untouched and is the radio's alone. Follow-up on a record by hand is a point.

- **`store/status.ts`**: `hasStatusChain(entry)` — the one definition: a `message_out` on
  transport `mesh`. `statusOf(entries, message)` now takes the message entry and returns
  `Status | null`: the chain's latest status for a radio message (pending when nothing refers
  to it), null for a message on any other transport, and null for anything that is not a

## Decisions taken

- **No `ØVELSE` prefix on a record by hand.** P1-05 put the prefix on every transport; the
  text protocol defines it "before `#<n>`" and says it is for the humans reading their
  phones. A plain record has no `#n` to put it before and goes on no phone, and the drill is
  on the incident and the whole frame already; keeping it would also have made `bodyOf`
  (no `seqNo`, so no prefix split) carry "ØVELSE " into every point title and courier
  prefill. Flagged for `docs/decisions.md`.
- **No byte limit on a record by hand.** The 160 bytes are MeshCore's; a courier note can
  be long. The New record form already said "no radio limit applies here" (P3-01) while the
  store still enforced one; now neither does.
- **`statusOf` takes the entry, not the id** — the pure function and the store's. The
  task says `statusOf` returns null for a non-mesh message; a function given only an id and
  the entries referring to it cannot know the transport, and looking the message up in the
  same array "if it happens to be there" would have been a heuristic. Every caller had the
  entry. The store's `statusOf(id)` looks it up and refuses an unknown id: a status of
  nothing is not pending.
- **A status change referring to a message by hand is ignored, not rendered.** The store
  cannot write one (`appendStatusChange` refuses) and the contract forbids it; one found in
  data is dropped from the view like a stray `sent` on a point. No tolerance code, no
  migration (decided 2026-11-16).
- **Mark is offered on a radio message only** (`transport === "mesh"` in the pure rule, not
  only `status !== null`), so the rule reads as the contract does and an inconsistent input
  can never show the button.
- **The open row of a record by hand offers the point action and Correct.** The task lists
  "Reply/Correct/point actions"; an outgoing message cannot be replied to (a reply's target
  is a `message_in`, `ReplyTargetError`), so Reply is not offered there, as it never was.
- **The courier copy's point is opened on the copy, titled from its text**, before the
  original is closed, so a refused close leaves the copy and its point on the screen. The
  reason on the original is "sent via Courier" with the transport word only (the `{n}` is
  gone from the reason, the toast and the help text). The order of the three writes is
  copy, point, close.
- **"Add to journal"** is the button for all three kinds, the words P3-01's `journal.add.save`
  had; `send.record` is gone as the task lists it. Nothing else on New record changed: the
  form never had a `#n` preview to remove, only a comment that claimed a number.
- **The style guide's "by hand" row became "a roger recorded by hand"** on a radio message:
  the sample set still shows every state the column has, and the manual case the contract
  keeps.
- **The screenshot seed keeps the walkthrough's point and its close** (the script used to
  skip every `closed` status change; now only the incident's own), so the Points card
  shows "Vis lukkede" with two and the print block two closed points; a reply by phone to
  Grethe shows a plain outgoing row at the top of the journal.
- **Prettier** run on every touched file that was formatted on `main`; `README.md`,
  `index.ts`, `journalStore.ts`, `journalStore.test.ts`, `outgoing.ts`, `outgoing.test.ts`,
  `outbox.svelte.ts`, `outbox.test.ts`, `status.test.ts` and `types.ts` were unformatted on
  `main` and are left so (the P1-01 follow-up stands). `incoming.ts` came out of the editor
  as CRLF and was converted back; every changed file is LF.
- Candidates for `docs/decisions.md` (the chain-is-the-radio's row is already there): no
  drill prefix and no byte limit on a record by hand; the courier copy of a given-up radio
  message carries a point.
