## Done

A row is one line of fixed height, at rest, under the pointer and with the focus; a click on
it (or Enter / Space) opens it in place, and the open row shows its history with times and
operators, its reply links and exactly the actions that apply to it. One row is open at a
time. The hover reveal and the History / Hide history / Recipients buttons are gone, with
their keys.

- **`components/Row.svelte`** (new): one row of a row list — the `<li>` with the cells on a
  `.row-line` that is the row's one button (`role="button"`, the roving `tabindex`,
  `aria-expanded`; `aria-controls` to the `.row-area` while open) and, under it, the area
  the list puts there. A click on the line toggles unless it lands on a control inside the
  line or ends a text selection inside the row (`lib/rowOpen.ts` `clickToggles`); Enter and
  Space on the line toggle, as on a button. A row with nothing to open (`openable={false}`)
  is a plain line with no role and no `aria-expanded`; a send-to-all row with nothing to
  retry opens on its recipients alone (`hasArea={false}`). Nothing in it answers to hover.
- **`components/RowHistory.svelte`** (new): the open row's history as the 14 px `.row-detail`
  list — one line per transition of an outgoing message (time, what happened, the roger's
  source as a jump when the list can jump, the operator), the corrections of a transition,
  then the versions of a corrected text (the original, every correction; P3-02). Nothing
  when the row has no history. Shared by the journal and the handover page.
- **`lib/rowOpen.ts`** (new, pure): which row is open — `OpenState { row, batch }`,
  `toggleRow` (a batch toggles its recipients and closes any other row; a recipient toggles
  inside its batch; any other row closes the batch and every other row), `isOpen`,
  `closeOne` (Esc: the open row first, a recipient's batch stays, then the batch),
  `openRowId`, `revealRow` (a jump to an entry opens the row that shows it — a batch on the
  recipient that holds the entry), and the click rule `clickToggles` with
  `CONTROL_SELECTOR`.
- **`lib/rowActions.ts`** (new, pure): the action set per row kind — `messageActions`
  (Retry when given up or Send when never sent and nobody is sending it, both on the page's
  `canRetry`; Mark while not confirmed, on a transport, nothing in flight; Correct always),
  `entryActions` (`message_in`: Reply, Correct; `note`: Correct; the incident's own status
  rows and an orphan correction: nothing), `batchActions` (Retry all given up when any
  recipient can be retried).
- **`components/Timeline.svelte`**: every row a `Row`; the line is time · who · body ·
  status column and nothing else — the "↳ answers ‹time›" mark left the body. The area of a
  message row: `RowHistory` (the transitions, then the versions), the "↳ answers ‹time›"
  link as a `.row-links` line, then the Mark form or the Correct form in place of the action
  row while one is open, else the action row (Retry / Send, Mark, Correct per the rule); of
  an entry row: the versions, the "answered ‹time›" links, the Correct form or Reply /
  Correct; of a batch row: "Retry all given up (n)" (the `queue.retryAll` key, each
  given-up recipient handed to the outbox in turn), then one `Row` per recipient under it,
  nested, each with its own line and area. `opened` is the one `OpenState`; `toggle` runs

## Decisions taken

- **The row's line is the button, not the row.** A list item's role does not take
  `aria-expanded`, and a `<button>` cannot hold the buttons of the area it opens; so the
  cells sit on a `.row-line` (`role="button"`, `tabindex`, `aria-expanded`) that is a
  subgrid of the row's subgrid, the area a sibling under it, the row's padding and tint on
  the row. The P2-03 focus-ring rule (`-2px` on the row) went with it: the line sits inside
  the row's padding and the global ring fits. The reply marks ("↳ answers 19:03") moved from
  the body into the area, so the line at rest holds no control — the task's "nothing else".
  Candidate for `docs/decisions.md`.
- **Enter and Space are the line's own keys**, handled in `Row.svelte` as a button handles
  them, not through the shortcut dispatcher: the handover page then gets them without a
  registration, and the dispatcher skips a key the row took (`defaultPrevented`). The
  `expandRow` entry stays in the documented set with both keys (the resolver names Space
  too) so the overlay lists them; nothing registers for it any more.
- **"Retry (only when given up)" is read with the page's rule**: `canRetry` on the journal
  page is a mesh message nobody is sending that is given up *or never sent*; the second case
  keeps its button, labelled Send (P2-03's "Send now" for a message left pending by a crash).
  Dropping it would take away the one way to send such a message. Flagged.
- **Esc belongs to the list only while the focus is in it or nowhere.** The timeline's cancel
  handler is asked before the compose forms' (it registered last); with a row open, Esc in
  the compose textarea would close the row instead of dropping the reply link. A form in the
  row is cancelled first, from anywhere, as before.
- **A jump opens the row it lands on.** The open-items card's "click = go to the entry" now
  opens the row it scrolls to (a batch on the recipient that holds the entry), as do the
  reply marks and a roger's source: that is "the same behaviour on the open-items panel"
  for a card whose rows are jump buttons, not journal rows.
- **One row open across the handover page**, not per list. A row of the open-orders list
  opens only when it has history (a pending order has nothing to show and is a plain line);
  given-up and unanswered rows always have actions. The quiet-radios list is register rows
  with one action and keeps that button on a line under each row — they are not the "row
  component", and a click to reveal one button would be friction for nothing.
- **A send-to-all row holds its recipients.** Open, it shows one `Row` per recipient under
  it; a recipient opens inside the batch without closing it (the one exception to "one row
  open"), another recipient replaces it, Esc closes the recipient first and the batch
  second, the batch's own line closes both, any other row closes everything. "Retry all
  given up" is the batch's action row, shown only when a given-up recipient can be retried;
  it hands each to the outbox in turn (the journal's single Retry path, no gap between
  them). A batch with nothing to retry has no area, only its recipients. The
  `queue.retryAll` key ("Retry all given up ({count})") is reused; no new key.
- **The incident's own status rows do not open**: nothing to show (no history on screen since
  P3-02, no action). They stay J / K stops with the tint and the tooltip.
- **The height is measured in the screenshot run.** There is no DOM harness (P1-02's
  follow-up stands) and a DOM without layout cannot measure; the script already drives the
  built app in Chromium, so it measures every row at rest, hovered and with its line
  focused and fails on a difference. The other half of the acceptance line — no `:hover`
  rule changes a box property — is a vitest test that parses the sheet.
- **`data-expanded` is `data-open`**, the task's word; nothing outside the sheet, the timeline
  and the style guide keyed on it.
- **Prettier** run on every touched file (all were formatted on `main`) and on the six new
  ones; every changed file is LF. **The screenshot set was regenerated whole** (the counts
  under *Verify*).
- Candidates for `docs/decisions.md`: the row's line is the button, the row opens on click
  and nothing on hover; one row open at a time, a batch the container of its recipients.
