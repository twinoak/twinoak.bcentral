## Done

The staff can stop waiting for a confirmation that is not coming. Close on an unconfirmed
radio message — sent, delivered or given up, and not transmitting — opens one small field
"Note (optional)" with Close and Cancel; Close without typing closes at once. The message
leaves "Unconfirmed messages" and the handover's lists as `closed`, a terminal status that
is recorded honestly as *closed by the staff*, never as confirmed. Mark keeps roger and
given up with a required reason for the cases where the staff do know.

- **`store/outgoing.ts`**: `closeByHand(store, message, { operator, note })` appends one
  `status_change` `closed` with the note as its text (trimmed; empty allowed and stored as
  `""`) and the operator. `CLOSABLE_STATUSES` = sent, delivered, given up and `isClosable`;
  refused with `CloseError`, nothing written, on a pending message (nothing went anywhere:
  it is sent, marked or left), on a final one (roger or closed), on a message without a
  chain (phone, courier, verbal) and on anything that is not a `message_out`.
  `recordManualStatus` now refuses a closed message too ("closed is final").
- **`store/status.ts`** needed nothing: `statusOf` returns the chain's latest, so `closed`.
  **`store/incoming.ts`** needed nothing: `isOpenForRoger` is sent or delivered, so a late
  `R` / `Rn` for a closed message is stored as an ordinary `message_in` with no status
  change — tested in `incoming.test.ts`.
- **`store/journalView.ts`**: `closed` is in the strip's chain (`StripKind`, `CHAIN`), the
  last item of a closed message's strip with the note as its text; an empty text is read as
  none (`textOf`). `BatchCounters.closed` counts closed recipients. `MessageView.lateRogers`
  — the field's `Rn` for a closed message received after the close — by `lateRogersOf`
  (exported, pure): the same counterparty, later than the closing status change, and the
  incoming text trimmed matches rule 1's regex with n = the message's own `seqNo`; a bare
  `R` names no message and is not listed. `lateRogerIds` collects them over a list for the
  handover. `slowestStatus` ranks closed just below roger (final, not a confirmation).
  `openItems` leaves a closed message out, like a confirmed one (the existing rule; said in
  the comment, tested).
- **`store/handoverView.ts`**: a closed message is in neither list (the existing rule,
  tested); `unansweredIncoming` leaves out a late `Rn` for a closed message — it is the
  field's answer to it, arrived late, not something the next operator has to answer.

## Decisions taken

- **Close sits first, before Retry.** The task: "the Close action is the routine one and
  sits first". On a given-up row the action line is Open point · Close · Retry · Mark ·
  Correct.
- **Pending is not closable.** The task names sent, delivered and given up; a pending
  message has not gone anywhere, so the row offers Send, Mark, Correct as before. A
  given-up message waiting in the paused queue (P3-08's retry without a radio) is still
  given up and offers Close, which takes it out of the queue (`sendActions.closeByHand`
  cancels first, like a mark).
- **The handover's old Close is this Close.** The given-up list's Close recorded a roger
  with a required reason — exactly the "manual confirmed with a reason which claims
  something the staff do not know" the task's *Why* names. It now writes `closed` with the
  optional note; Send by courier (which still closes the original with roger and the
  reason "sent via Courier", P3-07's rule, untouched) and Retry stay. The open list's rows
  gained Close too, since the task names "the handover list". The handover has no Mark
  (roger by hand with a reason); that is the journal's row. Flagged under *Follow-ups*.
- **The side card's Close is a line under the jump button**, as the Points card's Close
  (P3-05): the card's row is one button and a button cannot hold another; a fourth column
  on the 320 px card would leave the text about 80 px. The line is the row-actions' compact
  28 px. The card is taller for it (one line per closable item); flagged.
- **The late `R` is listed by the exact `Rn` match only.** The task says "show it by the
  Rn match". A bare `R` for a closed message (rule 2 stores it as plain when nothing is
  open) names no message and is not listed — listing it would be a guess. The match is
  the contract's regex on the trimmed text with n = `seqNo`, the same counterparty, and
  later than the closing status change (the store's ordering). An `Rn` that arrived before
  the close — on a given-up message, say — was plain before this task and stays so.
- **A late `Rn` is not an unanswered incoming message on the handover.** It is the closed
  message's answer, arrived late; the handover's list exists to find what the next operator
  has to answer, and that is not it. The same pure rule (`lateRogerIds`) decides; the
  contract is untouched (the entry is an ordinary `message_in`, and the list is a view).
- **Closed ranks below roger in a batch's slowest status** (final but not a confirmation),
  so a batch whose recipients are all closed or roger reads "closed", and one with any open
  recipient reads that recipient's state as before.
- **The dash replaces a cross in the confirmed slot** when a message given up at "confirmed"
  (sent, delivered, no ack of the roger kind — a manual give-up) is then closed: the slot
  holds one symbol and the later, terminal state wins; the given-up is in the history. A
  cross in the sent or delivered slot stays beside the dash.
- **An empty note is stored as `""`**, as the task says ("stores an empty text"), and every
  reader (`textOf`, `withDetail`, `historyDetail`) treats `""` as no text, so nothing shows
  "closed · ".
- **The history line says "closed by the staff"**, not the bare status word, so the line
  cannot be read as a confirmation; the operator cell says who. The acceptance's "closed
  by Thomas 14.40" is that line: time · closed by the staff · the note · Thomas.
- **`L` opens the row first when it is closed**, as `P` does (P3-05), so the form has a
  place; on a row that offers no Close (pending, confirmed, closed, transmitting, not a radio
  message) `L` does nothing and the key falls through.
- **`rowActions.ts` imports `isClosable` from `store/outgoing.ts`**: one definition of the
  closable statuses for the row rule, the side card, the handover and the store's refusal.
- **Prettier** run on every touched file that was formatted on `main` and nothing else;
  `outgoing.ts`, `outgoing.test.ts`, `README.md` and `docs/design.md` were unformatted on
  `main` and are left so (the P1-01 follow-up stands). `incoming.test.ts` came out of the
  editor as CRLF and was turned back to LF; every changed file is LF.
- Candidates for `docs/decisions.md`: `closed` is the staff's way out of the unconfirmed
  list and is never a confirmation; a late `R` is an ordinary incoming message, shown on the
  closed row by the exact match; the handover closes with `closed`, not roger.
