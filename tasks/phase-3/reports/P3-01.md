## Done

The compose card's two tabs now have one job each. Tab 1, **New record** (da: *Opret
registrering*), is everything the operator writes into the journal by hand; tab 2,
**MeshCore**, is a message over the radio and nothing else. Reply and "send by courier" open
the tab the entry's transport decides.

- **`store/record.ts`** (new): `recordByHand(store, input)` — the New record tab's one store
  path. `type` is `note` / `message_in` / `message_out` (`RECORD_TYPES`, the select's order).
  A note goes through `appendNote`; an incoming message through `appendMessageIn`
  (manual.ts, unchanged: no `dedupeKey`, no status, mesh refused); an outgoing message
  through `composeMessage` with the recipient's next `#n`, the transport as chosen and
  `refersTo` when it answers a row — exactly what the compose form stored for a non-mesh
  message before. Mesh is refused on both message kinds (`ManualEntryError`), as is a
  missing or unknown counterparty; nothing is reserved on a refusal.
- **`store/outgoing.ts`**: `composeMeshMessage(store, input)` — the MeshCore tab's path:
  transport `mesh` always; the recipient is checked against the register first and a
  pending row (P1-06) or any unknown id is refused with the new `RecipientError` before
  anything is reserved. `composeMessage` itself is unchanged (the batch, the status request
  and the tests compose through it as before).
- **`store/handover.ts`**: `sendByCourier` → `resendByHand(store, original, { operator,
  transport, body, reason })`. The copy's transport and text are now the form's (the
  operator may edit the prefilled text or pick phone or verbal instead of courier); the
  radio is refused (`HandoverError`); the rest is as P1-08 — given-up checked, the copy
  written first, the original closed with `roger` and the reason.
- **`lib/composePrefill.ts`** (new, pure): which tab an action opens and with what.
  `replyPrefill(entry)`: an incoming mesh message → `{ tab: "meshcore", counterpartyId,
  replyTo }`; one by phone, courier or verbal → `{ tab: "record", type: "message_out",
  transport: the same, counterpartyId, text: "", replyTo, closes: null }`.
  `courierPrefill(original)` → `{ tab: "record", type: "message_out", transport:
  "courier", counterpartyId, text: bodyOf(original), replyTo: null, closes: original }`.
  Anything else throws `PrefillError`.
- **`store/index.ts`**: `recordByHand`, `composeMeshMessage`, `resendByHand` (the reason
  built from `handover.givenUp.resentReason` with the transport word and the copy's `#n`);

## Decisions taken

- **"New record"** for tab 1 (the task's proposal over "Log by hand"): it names the thing
  made — a record in the journal — and pairs with the button "Record", which the task moves
  there; "Log by hand" names the manner. The Danish is the decided "Opret registrering".
- **No free-text counterparty** on New record (the task's lean): the schema requires a
  register entry on both message kinds; a caller who is not in the register gets a
  `private` entry first, as an unknown radio does. The two selects and the store check
  (`ManualEntryError` on an unknown id, so an id that reaches the store by any route is
  refused too) say so.
- **The handover page hosts the tab, it does not navigate to it.** "Open tab 1 with …
  prefilled" is read as the tab's form, not the journal screen: the handover's compose card
  (P1-08: "everything open on one screen") now holds `ManualEntryForm` or `ComposeForm` by
  the action's prefill, titled as the tab it is. Leaving the handover page for the journal
  on every courier decision or phone reply would undo the page's point. The same prefill
  functions drive both pages, so the routing is one rule.
- **"Send by courier" no longer writes at once.** P1-08 wrote the copy and closed the
  original on the click; the task says the action opens tab 1 prefilled, so the write
  happens on Record. That gives the operator the text to edit and the transport to change
  (phone, verbal) before anything is stored — the courier may not be the one at hand. The
  original is still closed with `roger` and a reason when the record is stored, by the same
  function as before (`resendByHand`); the help text on the button says so. Flagged for
  `docs/decisions.md`.
- **The reason and the toast name the transport** ("sent via Courier as #4"; da "sendt via
  Bud som #4"), since the copy's transport is now the operator's choice; the earlier
  "sent by courier as #n" would lie for a phone copy. The transport word is the Via option's
  (`send.transport.*`), so it is capitalised mid-sentence; a lower-case set of the same
  words would be four more keys for one sentence — left as is, flagged.
- **`A` keeps the type as chosen.** P1-09's `A` put "Note" into the Kind select every time;
  with three types the task says only "`A` opens tab 1", so the key reveals the tab and puts
  the cursor in the text, and the type stays what the operator last set (Note on load, and
  after a reload). An operator logging three phone calls in a row does not re-pick the type.
- **Changing the type away from Outgoing message drops the reply link and the `closes`.**
  Only an outgoing record can answer a row or replace a given-up message; keeping either
  across a change to Note would store a note and silently lose the link (`recordByHand`
  does not read `refersTo` for a note), or worse, leave a `closes` armed for the next
  outgoing record. Dropped at once, visibly (the inline lines go).
- **The MeshCore store path checks the register itself** (`composeMeshMessage`) rather
  than `composeMessage`: the batch, the status request and 15 existing tests compose to ids
  without creating register entries, and the task asks the MeshCore tab to refuse pending
  rows, not every write. The New record path checks the same way for an outgoing message.
- **The shortcut action ids stay `newMessage` / `addNote`**; renaming them would touch
  `lib/shortcuts.ts`, its tests and `App.svelte` for no behavioural change. The overlay's
  words come from i18n and say what the keys open now.
- **`send.transport.mesh` stays** (Timeline, HandoverPage and PrintPage show the transport
  word on rows); `journal.add.save` goes (Record took its place, the task's wording).
- **Prettier** run on every touched file that was formatted on `main` and on the four new
  files; `outgoing.ts`, `index.ts` and `outgoing.test.ts` were unformatted on `main` and are
  left so (the P1-01 follow-up stands). `manual.ts` is CRLF on `main` and is untouched. Every
  changed file is LF.
- **The screenshot set was regenerated whole**, as the script does (it wipes the folder):
  32 of the 36 earlier files differ in bytes though their screens did not change (a newer
  Chromium, 157, than P2-05's run; the handover's compose card and the style guide's tab
  sample did change). Committed as the script wrote them, so the set is one browser's.
- Candidates for `docs/decisions.md`: the two tabs' jobs (by hand vs. radio, the transport
  never a choice on the radio tab); a reply's tab follows the incoming message's transport;
  "send by courier" writes on Record, not on the click, and the original closes then.
