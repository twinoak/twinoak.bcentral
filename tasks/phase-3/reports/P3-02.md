## Done

Correcting an entry is editing its text: Correct on a row hides the row's text and opens one
box under it holding the entry's current text, the cursor at the end; Save appends a
`correction` referring to the original entry with the whole corrected text; the row then reads
the corrected text with a "corrected" chip after the time, and History lists the original
and every correction. Nothing in the model changed.

- **`store/journalView.ts`**: `currentText(entry, corrections)` — the one place every screen
  reads an entry's text from: the latest correction's text when it has corrections, else its
  own. `textVersions(entry, corrections)` — the original then every correction in ULID
  order (empty when never corrected); `correctionsByTarget(entries)` — every correction by
  its `refersTo`, for screens that hold entries rather than rows; `splitPrefix(message,
  text)` — a message's text as its fixed `#n ` (or `ØVELSE #n `) prefix and the body

- **`lib/correctionForm.ts`** (new, pure): `correctionForm(entry, corrections)` → `{ target:

  typed)` — false while the trimmed text is empty or equals what the box opened with;

## Decisions taken

- **The form is on the line under the row, not in the body cell.** The first build put it
  in the body cell in place of the text; measured in the seeded journal at 1280 px the body
  column is 287 px (the batch row's four-counter strip takes its third, the time column
  carries the chip), so the label, the box and the buttons stacked on three lines. Under the
  row the form spans every column, as the status form does, and the label, the `#n`, the
  box, Save and Cancel sit on one line; the row's own text is hidden meanwhile, so there is
  one copy on screen (the task's point).
- **The chip is a plain `.chip`.** The task names `.chip-neutral`; the design language has
  no such class — neutral is the default `.chip` (`chipClass("neutral")` is empty). The glyph
  is a seventeenth icon, `edit` (a pencil), rather than a text glyph: the set's rule is that
  an icon is a state or an action, and "corrected" is a state.
- **Correct is offered on `note`, `message_in` and `message_out` only**, the task's list.
  Before, every entry row had the button, so the incident's closed / reopened rows and an
  orphan correction row lose it; a correction of a correction is thereby impossible from the
  screen (the chain is one original with N corrections). Corrections such rows already carry
  (imported data) still show: the chip, the current text and the history work on any row.
- **The latest correction is the highest ULID**, as the task says, not the latest timestamp:
  `textVersions` sorts by id, so a clock set back between two corrections does not swap
  them. `buildTimeline`'s per-row lists stay in `compareEntries` order; the two agree
  whenever the clock did not move.
- **History on entry rows.** The task wants the expanded row's history to list the versions;
  a note or an incoming row had no history before, so such a row gets the History (n)
  button when it has corrections, opening a `.row-detail` of versions like a message's. On a
  message row the versions follow the transitions and the count is the number of lines.
  P3-04 replaces the toggle with click-to-open; the versions list carries over.
- **The chip in the time cell widens the time column** for every row of a list that holds a
  corrected row (a `max-content` subgrid column; about 45 px at 1280). Kept, since the task
  places the chip after the time and P3-03 takes the times out of the list; flagged.
- **The printed marker carries the time and the operator** — "(corrected 20.41 · Thomas)"
  rather than a bare "(corrected)": on paper there is no tooltip and no history to open, and
  the correction rows that carried them are gone. The footnote lines carry the same for the
  original and any superseded correction.
- **The stored text is prefix + trimmed body.** `appendCorrection` trims the whole text as
  before; the form refuses an empty or unchanged body before that, so `#12 ` alone can never
  be stored.
- **No Ctrl+Enter in the box** (not in the task; the compose forms have it) — flagged.
- **Prettier** run on every touched file (all were formatted on `main`) and on the three new
  ones; every changed file is LF. **The screenshot set was regenerated whole**: 20 of the
  earlier 40 files differ in bytes — the journal captures through the wider time column, the
  print PDFs through their timestamps, the style guide through the new icon.
- Candidates for `docs/decisions.md`: a correction is the whole corrected text and always
  refers to the original (one original, N corrections); the row reads the latest correction's
  text; the `#n` prefix is not the operator's to edit.

## Follow-ups

- [ ] The "corrected" chip widens the time column of the whole list (a `max-content`
      subgrid column) by about 45 px at 1280 whenever a corrected row is in it. P3-03 takes
      the times out of the list; decide the chip's place then (the status column's slots, or
      the body).
- [ ] The reply marks' tooltips (`title={answers.text}`, `title={reply.text}`) and a roger's
      "from “R1”" line still show the referenced entry's original text, not its corrected
      one: the timeline has no corrections map for arbitrary entries, only per row.
- [ ] A batch row's body (`bodyOf(first.entry)`) and the "send by courier" prefill
      (`courierPrefill`, `bodyOf(original)`) read the original text; a corrected recipient
      record or a corrected given-up message does not reach them. Both are a `currentText`
      call away once the caller has the corrections.
- [ ] Ctrl+Enter does not save the correction box (the compose forms save on it); Save is a
      click or Tab + Enter.
- [ ] A correction of a `status_change` (the incident's close reason, a transition in a
      message's history) can no longer be made from the screen; `appendCorrection` still
      accepts one, and imported ones still show.
- [ ] `print.corrected` and the footnote lines put the operator's name on paper per
      correction; if the staff want the printed journal shorter, a bare "(corrected)" with
      the versions in the footnote only is one key.
- [ ] No component test harness (P1-02 follow-up stands): the cursor at the end, the focus
      returning to the row, the chip's tooltip and the look are checked on the sources and
      by hand.
- [ ] The Danish of the new and changed keys was written by the session and awaits a human:
