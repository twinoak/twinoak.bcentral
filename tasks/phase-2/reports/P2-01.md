## Decisions taken

- **`<Icon>` component, not strings in markup** (the task's lean): size, stroke, `currentColor`
  and `aria-hidden` are one place; the data stays a plain table in `lib/icons.ts`, so a
  script or a test can read it without Svelte. Icons are drawn on a 20-unit grid so the
  1.75 stroke is 1.75 px at 20 px.
- **`transition.css`** rather than letting bare buttons and inputs fall back to browser
  defaults: the task allows odd screens, but a reviewer walking the journal in between would
  have had unstyled controls, and P2-02 … P2-04 have to delete those rules anyway; a named
  file with a deletion note is easier to empty than rules scattered in `base.css`. Nothing in
  it is new and nothing new may use it. Flagged for P2-05 to delete.
- **Sizes in rem, the document's px at the 16 px root.** The document writes 36 px, 24 px,
  360 px; the text-size setting scales the root, and a 36 px button at 21 px text would not
  hold its label, so every size is `rem` with the px in a comment (`2.25rem` = 36). The
  largest capture shows everything scaling together.
- **`--rule-2` darkened, `--rule` not checked.** The document's `#bac1ca` cannot reach 3:1 on
  white; the value is `#7f8791` (3.6:1 on white, 3.3:1 on `--bg`). `--rule` (row separators,
  card borders) stays the document's `#dde1e6` and is not in the pair list: a separator is
  decoration (P1-09's reasoning kept); in high contrast it is black anyway.
- **Chips in a strip drop their background.** The document says a strip is "an inline run of
  chips separated by ·, 14 px, dot per state"; five tinted boxes per row would make the
  journal loud, and "roger ok filled" only means something against "delivered ok" when the
  dot carries the state. So `.strip .chip` is dot + word in the status colour on nothing, and
  the hollow / filled dot tells delivered from roger. A chip outside a strip keeps its tint.
- **Inline messages carry the pair** (a tinted 14 px line); a field error does not (14 px
  danger with an icon, as the document writes it).
- **The glyph is in the markup** (`<Icon name="warning">` in a field error or a message), not
  CSS `content`: the icon set exists for it, and a CSS glyph would need its own Unicode
  character per state.
- **`.rows` styles every child**, not a `.row` class: the screens already use `class="row"`
  for form rows, and `.dot` for the `·` separator, so those names were avoided (`.chip-dot`).
- **The style guide is in the UI language.** Every sentence on it is one of the app's keys
  (`home.intro` for the type specimen, the status words, the empty-state text, the notices);
  headings are the token and class names in `<code>`; the pair descriptions are the check's
  own English, as in the test output. Seven keys were added for the page's own words.
- **The style guide bypasses the operator-name gate** (`App.svelte`): it is for the reviewer,
  records nothing, and is reached by URL.
- **High contrast keeps the accent and the four hues** (as P1-09 kept navy, red and green):
  each passes on white; the tints go white and every chip, tinted message and selected row
  gets an edge in that mode so the state is not in the background alone.
- **Colour-literal regex**: 3–8 hex digits after `#` not followed by `[\w-]`, so `#/journal`,
  `{#each}` and `#12` pass and `#123` would not — the style guide's number specimen is
  `#7 #12 #99` for that reason; a real message `#123 …` lives in data, not in a `.svelte`
  file.
- **`font-display: block`**: the file is local and precached; a short blank beats a reflow in
  the middle of a row.
- **Prettier** was run on every new file and on the touched files that were formatted
  before; `SettingsPage.svelte` and `app/README.md` were unformatted before and are left so.
  Every changed file is LF.
- Candidates for `docs/decisions.md`: sizes in rem with the document's px at 16; `--rule-2`
  at 3:1 on every grey and `--rule` unchecked; strips without chip backgrounds.
